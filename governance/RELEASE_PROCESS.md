# HCOS™ Release Process

## Purpose

This process defines how approved HCOS work is prepared, versioned, documented, and released.

## Release Steps

1. Confirm approval status and responsible steward.
2. Update document metadata and revision history.
3. Review links, dependencies, identifiers, and file naming.
4. Update `CHANGELOG.md`.
5. Assign the appropriate semantic version.
6. Create the Git tag and GitHub Release when applicable.
7. Publish or distribute approved artifacts.
8. Communicate material changes to affected repositories or users.
9. Record post-release stewardship responsibilities.

## Release Notes

Release notes should explain:

- what changed
- why it changed
- who may be affected
- compatibility or migration concerns
- superseded artifacts
- known limitations

## Emergency Corrections

Urgent safety, legal, factual, or integrity corrections may use an expedited process. The rationale and subsequent review must still be documented.
