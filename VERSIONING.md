# HCOS™ Versioning

## Purpose

HCOS™ uses Semantic Versioning to provide a consistent and transparent approach to documenting changes across frameworks, standards, prompts, instruments, examples, and supporting documentation.

## Version Format

```text
MAJOR.MINOR.PATCH
```

## Version Definitions

| Change | Meaning | Example |
|---|---|---|
| Major | Substantial conceptual, architectural, or compatibility-breaking revision | `2.0.0` |
| Minor | New sections, guidance, capabilities, or examples that remain broadly compatible | `1.1.0` |
| Patch | Corrections, clarifications, formatting improvements, or minor refinements | `1.1.1` |

## Release Alignment

Where appropriate, align:

- document versions
- `CHANGELOG.md` entries
- Git tags
- GitHub Releases
- published downloads

## Suggested Git Tags

```text
v1.0.0
hcos-i-003-v1.1.0
hcos-a-001-v2.0.0
```

## Draft Documents

Draft status and version are separate concepts. A draft may still progress through versions while being refined. Publication status must remain visible in document metadata.

## Guiding Principle

Versioning should make change understandable. It should not create unnecessary administrative burden.
